# PAI architecture constitution

Applies to this entire repository.

- The objective is excellent student counseling across languages and education systems.
- Preserve original student language, qualifications and grades. Unknown remains unknown.
- Semantic understanding proposes interpretations; deterministic gates enforce evidence, ownership, consent and integrity.
- Never introduce country/degree keyword ladders, implicit GPA scales or field-name importance weights.
- Only canonical domain services write student truth. Pending/conflicting claims remain proposals.
- Keep chat streaming fast: context and recall overlap; recall and understanding have short, configurable deadlines. Cancel unfinished work.
- Background intelligence must be idempotent, lease-fenced, deletion-aware and checked against its input revision before publication.
- Record the actual inputs to goal analysis. Invalidate by those dependencies, with conservative fallback for legacy analyses.
- Preserve tenant isolation and sensitive-field filtering in retrieval, prompts, caches and logs.
- Use distributed limits and durable worker health in production; never trust unverified client identifiers.
- Keep qualification mappings optional and evidence-backed; do not invent a global equivalency ladder.
- Use disposable local/CI databases for checks. Never run truncating fixtures against a deployed database.
- Respect the user's verification budget. Prefer focused static/import checks when a full suite is not requested.
- Never commit secrets, local environment files, generated analysis caches or credentials.
- Preserve GitHub history and authorship unless the user explicitly requests a history rewrite.
